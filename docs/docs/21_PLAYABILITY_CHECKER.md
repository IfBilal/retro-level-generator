# 21 — Playability Checker (physics-consistent A* + MarioEval.jar bridge)

> **Module:** `src/text2mario/playability/checker.py` (+ `jar_bridge.py`). **Physics contract:** doc 27 §4 (owner of `app/static/game/physics.json`). **Gates:** G-P5b (validation, **Day 7**), used by G5 (doc 20), by eval `playable` (doc 22 §3.6) and by E4 only after G-P5b passes. **Days:** v0 Day 5, v1 + jar bridge Day 6, validation Day 7.
> Purpose of the design: a "Verified beatable" verdict is a promise to the player, so the checker must be **conservative** (its moves are a subset of what the game and a human can do).

## 1. Two tiers
- **Tier 1 (fast, in-app, pure Python/NumPy):** tile-graph A* with jump arcs taken from `physics.json`. Median < 1 s for a 121-column level (NFR-PERF-05, SHOULD; to be measured Day 6).
- **Tier 2 (optional, offline):** MarioEval.jar (Baumgarten A*) via `subprocess.run(["java","-jar",<abs path>,...], cwd=<fresh temp dir>, timeout=60)`; level written with `grid_to_vglc_text`. Used only for G-P5b agreement and the jar subset of the one-shot test. Needs Java (`env/capabilities.json`). Never imported, never needed by the app (NFR-SEC-04).

## 2. Inputs, outputs
```python
def check_level(grid: np.ndarray, *, mode: Literal["scene","level"], framing: Framing|None,
                physics: Physics, budget_nodes: int, noise_profile: float = 0.0) -> CheckResult
@dataclass class CheckResult:
    status: Literal["solved","unsolved","timeout"]
    path: list[tuple[int,int,str]]      # (col,row,move) for replay / future ghost bot (seam S-1)
    fail_col: int | None                # furthest column reached when unsolved (drives the window resample, G5)
    nodes: int; seconds: float; physics_sha256: str
```
`noise_profile` is reserved for the difficulty-dial seam (S-10), fixed at 0. **Timeouts count as unsolved** and are reported (`timeout_rate` must stay < 1 %; otherwise raise the budget, doc 25 R-5.5).

## 3. Modes
- **Scene mode** (16-wide windows): spawn = leftmost standable cell on the left edge, goal = reaching the right edge column.
- **Level mode** (framed): spawn = `framing.spawn`, goal = `framing.flag.col` (doc 29).

## 4. Rules (mirror doc 27 §4.4; no constants hard-coded)
1. Solid tiles = `solid_tile_ids`; passable = `passable_tile_ids`; enemy cells (`hazard_tile_ids`) are hazards: the path may not occupy a hazard cell, and a jump over one must clear it with the arc.
2. Moves from a standing cell: walk/run one tile (horizontal speed class `walk` or `run`), step up <= `checker_max_rise` (4), drop down, **jump arcs** to landing cells using the envelopes `derived.checker_max_gap_same_height / landing_lower / landing_higher` (per speed class and height difference). Walk-offs allowed. No coyote time, buffering or mid-air steering is assumed (conservative).
3. Falling below row 15 + `death_fall_margin` = death (state pruned). Left/right world edges are walls; the top is open.
4. Cannons solid and non-firing (`cannon.fire_enabled = false`); bricks permanently solid.
5. Search: A* on states (col, row, speed class), heuristic = remaining columns to goal; node budget from config; deterministic tie-breaking.
6. The checker writes `physics_sha256` into the result; level JSON stores it (doc 29); the game compares (doc 27 §4.1).

## 5. `physics.json`
Owned by doc 27 §4.1 (gravity, jump_velocity, speeds, body sizes, tile id sets, margins, `derived` envelopes generated by `scripts/derive_physics.py`). The checker **only reads** it. `tests/test_physics_contract.py` fails when `derived` is stale. **Freeze:** physics is frozen at the end of **Day 6**, before G-P5b (Day 7) and before any use of `playable` in selection (this replaces the earlier "Day 9" freeze); changing it afterwards invalidates stored playability numbers.

## 6. Calibration on real levels (Day 5-6)
Run on all train and dev real levels (full width) and 16-wide windows. Target (from doc 27 §4.5): >= 90 % of train+dev full levels beatable; every failure classified (VGLC artefact, missing mechanic, physics too strict). The baseline rate is **measured, not assumed** (paper reports about 93 % for Baumgarten A*, F18). Tune only within the doc 27 §4.5 ranges, log in the ledger. **Never look at test levels.**

## 7. Jar bridge
`grid_to_vglc_text(grid)` -> file -> jar -> parse "solved/failed" (and a timeout counter). The 300-item agreement set and the confusion matrix, Cohen's kappa and the **false-"verified" rate** (fast = solved, jar = failed; warn if > 10 %) are produced by `scripts/gate_p5b.py` (doc 24).

## 8. Hand-labelled set (Java-free validation, G-P5b fallback)
50 levels drawn **only from train/dev real levels and Phase-3 unconditional samples**: ~25 real full levels or windows and ~25 samples/edited windows; stratified so both labels occur. Each level is labelled "beatable / not beatable" by **two members independently**, by looking at the render and, when in doubt, playing it in the browser game; disagreements are settled by playing. Labels go to `reports/gates/P5b/human_labels.csv` with labeller initials. Gate: agreement >= 90 %.

## 9. Validation protocol and the circularity rule
1. Day 5-6: build, calibrate, freeze physics. 2. Day 7: run `gate_p5b.py`; write `RESULT.json`. 3. Only if `pass: true` may `playable` appear in S, in `eval.composite`, or in any model/CFG selection (ledger E4). Before that, use `S_noplay`. 4. Day 11: re-run agreement on 30 generated full levels as a non-gating monitor. 5. Report the agreement, kappa and the false-"verified" rate; state that "verified" means "the checker says beatable", validated against the jar/human labels, not "proven for humans" (doc 32 §3.1).

## 10. Tests (`tests/test_checker.py`)
micro-levels (flat floor solved; gap > max jump unsolved; gap <= max jump solved; wall > max rise unsolved; staircase solved; pipe <= jump height solved); `test_physics_single_source`; `test_real_levels_band`; `test_jar_bridge_format`; `test_jar_runs` (needs Java); determinism; timeout reported as `timeout`.
